🔢 The Naive Method: Explicit Counting

To add $5 + 7$, we initially learned to draw $5$ dots and $7$ dots, then count all $12$ dots.

$\bullet\bullet\bullet\bullet\bullet \quad + \quad \bullet\bullet\bullet\bullet\bullet\bullet\bullet \quad = \quad 12$
  • Imagine adding large numbers like $473 + 695$ by drawing dots!

⚡ The Algorithmic Breakthrough

In the Indian base-ten place-value system, we write numbers aligned on the right and add column-by-column:

  4 7 3

1 1 6 8

Section 11.1.1

The Formal Addition Algorithm

Pages 37–38
📋 Five Formal Steps to Add Two Numbers
  1. Step 1: Write numbers one below the other in the Indian base-ten system, aligned from right to left.
  2. Step 2: Add rightmost digits. If sum $< 10$, write sum below, $carry = 0$. If $\ge 10$, write units digit, $carry = 1$.
  3. Step 3: Move left one column. Add two digits plus $carry$. If sum $< 10$, write sum, $carry=0$; else write units digit, $carry=1$.
  4. Step 4: Repeat Step 3 until there are no more digits left on the left.
  5. Step 5: If final $carry = 1$, write $1$ to the left of the bottom row.
💡 Foundational Assumptions
  • Primitive Step: We assume we already know how to add single-digit numbers directly without counting.
  • Composition: Any algorithm is built from verified elementary atomic operations.
  • Deterministic: Following rules rigorously ensures the exact same correct result every time.

Analysis & Justification

Why the Algorithm Works & Efficiency Scaling

Pages 38–39
⏱️ Counting Dots vs. Digit Columns

Suppose counting 1 dot takes 1 second, while single-digit addition takes 15 seconds:

Operation Explicit Counting Algorithm Time
$33 + 27$ $\approx 1\text{ minute}$ $\approx 30\text{ seconds}$
$334 + 272$ $\approx 10\text{ minutes}$ $\approx 45\text{ seconds}$
$3347 + 2729$ $> 1\text{ hr } 40\text{ min}$ $\approx 1\text{ minute}$

Adding a digit multiplies dots by $10\times$, but only adds one single column of work!

🎯 Mathematical Justification

Why does adding digits column-wise give the true sum?

  • We decompose numbers into units, tens, hundreds: $$N = d_0 \cdot 10^0 + d_1 \cdot 10^1 + d_2 \cdot 10^2 + \dots$$
  • Adding columns groups identical powers of ten.
  • Whenever a group sums to $\ge 10$, $10$ units of that power bundle into exactly $1$ unit of the next power of ten (the carry).

Section 11.2

Greatest Common Divisor (GCD / HCF)

Pages 39–40
🔍 Deconstructing the Definition

To find the Greatest Common Divisor directly from its definition:

  1. Compute Divisors: Calculate all positive factors of both numbers.
  2. Compare Collections: Identify the numbers that are present in both collections (common divisors).
  3. Find the Maximum: Pick the largest number among these common divisors.
$\gcd(m, n) = \max \big( \text{divisors}(m) \cap \text{divisors}(n) \big)$
🧩 Algorithmic Thinking in Action

Rather than relying on informal intuition, we break the task into precise programmable sub-goals:

  • Sub-problem A: An algorithm to find all divisors of any given number $n$.
  • Sub-problem B: An algorithm to systematically extract common elements from two lists.
  • Sub-problem C: An algorithm to locate the greatest element.

Section 11.2.1

Algorithm: Generating Divisors of $n$

Pages 40–41
📝 Algorithm to Find Divisors of $n$
  1. Start with an empty $\text{list-of-divisors} = [\,]$.
  2. For each number $j$ in the sequence $1, 2, 3, \dots, n$:
    • If $j$ divides $n$, append $j$ to the end of $\text{list-of-divisors}$.

Key Concept: Using variable names ($j$, $\text{list-of-divisors}$) allows precise step-by-step description.

⚙️ Execution Trace for $n = 18$
  • Start: $[\,]$
  • $j=1 \implies [1]$  |  $j=2 \implies [1, 2]$  |  $j=3 \implies [1, 2, 3]$
  • $j=4, 5 \implies$ not divisors (list unchanged)
  • $j=6 \implies [1, 2, 3, 6]$
  • $j=7, 8 \implies$ not divisors  |  $j=9 \implies [1, 2, 3, 6, 9]$
  • $j=10\dots17 \implies$ no divisor  |  $j=18 \implies [1, 2, 3, 6, 9, 18]$
$\text{divisors}(18) = [1, 2, 3, 6, 9, 18]$ (automatically sorted!)

Section 11.2.2 – 11.2.3

First GCD Algorithm: List Intersection

Pages 41–43
📜 The Complete Algorithm: $\gcd(m, n)$
  1. Let $\text{divisors-of-}m = \text{divisors}(m)$.
  2. Let $\text{divisors-of-}n = \text{divisors}(n)$.
  3. Start with an empty list $\text{common-divisors} = [\,]$.
  4. For each number $x$ in $\text{divisors-of-}m$:
    • If $x$ appears in $\text{divisors-of-}n$, add $x$ to $\text{common-divisors}$.
  5. Report the rightmost element of $\text{common-divisors}$ as $\gcd(m, n)$.
🎯 Textbook Example: $\gcd(375, 825)$

$\text{divisors}(375) = [1, 3, 5, 15, 25, 75, 125, 375]$

$\text{divisors}(825) = [1, 3, 5, 11, 15, 25, 33, 55, 75, 165, 275, 825]$

$\text{common-divisors} = [1, 3, 5, 15, 25, 75]$

Rightmost element = 75 $\implies \gcd(375, 825) = 75$.

For large numbers like $(54000, 81000)$, checking by eye is impossible without this systematic list comparison!

Data Structures & Intermediate Values

Pages 43–44
🗄️ What is a Data Structure?

During execution, algorithms calculate intermediate values that must be tracked, organized, and retrieved later.

  • Variables: Named placeholders ($j$, $m$, $carry$) representing values.
  • Lists: Ordered collections of elements, written as $[a_1, a_2, \dots, a_k]$.
  • A Data Structure organizes information to make algorithmic storage and manipulation efficient.

Section 11.3.1

Refining the GCD Algorithm: Three Optimizations

Pages 44–45
1️⃣ Single Combined Scan

Instead of two separate scans taking $m + n$ steps, test $j$ from $1$ to $\max(m, n)$.

If $j$ divides $m$, add to $m$'s list; if $j$ divides $n$, add to $n$'s list.

2️⃣ Direct Check up to $\min(m, n)$

A common divisor cannot exceed the smaller number!

Scan $j$ from $1$ to $\min(m, n)$. If $j$ divides both $m$ and $n$, add directly to $\text{common-divisors}$.

3️⃣ Eliminating Lists

Past divisors are useless once a larger one is found!

Track a single variable:

$\text{most-recent-common-divisor}$

Update whenever $k$ divides both $m$ and $n$. Final value is GCD!

Section 11.3.2

Analysis of Refined Algorithms: The Core Bottleneck

Pages 45–46
⚠️ The Unsolved Scaling Problem

Even after eliminating lists and scanning only up to $\min(m, n)$:

  • The work is still directly proportional to the value of the number, not the number of digits!
  • If the smaller number grows from 3 digits to 4 digits ($100 \to 1000$), work increases by 10 times.
  • From 3 digits to 5 digits ($100 \to 10000$), work increases by 100 times.
🎯 The Ultimate Algorithmic Goal

Recall our base-10 addition algorithm:

$\text{Work} \propto \text{Number of Digits (Length)}$

Can we design a GCD algorithm where the number of computational steps depends only on the number of digits rather than the magnitude of the numbers?

Section 11.3.3

Euclid’s Subtraction Algorithm & Geometric Tiling

Pages 46–47
📐 Fundamental Theorem: $\gcd(m, n) = \gcd(n, m - n)$

Assume $m \ge n$. Let $d$ be a common divisor of $m$ and $n$:

  • $m = a \cdot d$ and $n = b \cdot d$ for integers $a, b$.
  • $m - n = a\cdot d - b\cdot d = (a - b)d \implies d$ divides $(m - n)$.
  • Conversely, if $d$ divides $n$ and $m - n$, then $d$ divides $n + (m - n) = m$.
  • Hence, the common divisors of $(m, n)$ and $(n, m - n)$ are identical!
🧱 Geometric Visualisation: Tiling Rods

If a tile of length $d$ perfectly tiles both rods $m$ and $n$, it must perfectly tile the difference $(m - n)$:

Rod m (Length = ad)
ddd ... dd
Rod n (Length = bd)  |  Remaining: (m - n)
dd dd ... d
Stopping Condition: $\gcd(m, 0) = m$

Section 11.3.4

Āryabhaṭa’s Division Algorithm (499 CE)

Pages 48–49
🇮🇳 From Repeated Subtraction to Remainder

Repeatedly subtracting $n$ from $m$ until we cannot subtract anymore is simply computing the remainder:

$\gcd(m, n) = \gcd(n, m \bmod n)$

Featured in Indian treatises like Āryabhaṭa’s Āryabhaṭīya (499 CE), replacing tedious subtraction with long division!

  • $\gcd(99, 2)$ took 49 subtraction steps.
  • With remainder: $99 \bmod 2 = 1 \implies \gcd(2, 1) \implies 2 \bmod 1 = 0 \implies \mathbf{1}$. Solved in just 2 steps!
⚡ Classic Long-Division Steps
Calculating $\gcd(825, 375)$
$825 = 375 \times 2 + 75$  $\longrightarrow$ remainder $= 75$
$375 = 75 \times 5 + 0$    $\longrightarrow$ remainder $= 0$
Final Non-Zero Remainder $= 75$!

🎉 Efficiency Achieved: The number of reduction steps is now proportional to the number of digits in $m$ and $n$!

A Pinch of History

Al-Khwārizmī & The Origins of the Word "Algorithm"

Page 49
🏛️ The House of Wisdom, Baghdad

Muhammad ibn Mūsā al-Khwārizmī (780–850 CE):

  • Master Persian scholar who studied Indian astronomy and mathematics.
  • Learned Sanskrit and wrote a monumental treatise (~820 CE) introducing Indian place-value numerals and operations (addition, subtraction, multiplication, division).
  • 12th-century Latin translation: Liber Algorismi de numero Indorum ("The Book of Al-Khwārizmī on Indian Numerals").
📜 Etymological Evolution

How the name of a scholar became a cornerstone of modern science:

Al-Khwārizmī $\longrightarrow$ Algoritmi $\longrightarrow$ Algorism $\longrightarrow$ Algorithm

Originally, "algorism" strictly denoted an Indian method of decimal arithmetic! Today, it represents any unambiguous, step-by-step computational procedure.

Worked Representative Problems from Exercises

Problem 1 $\gcd(60, 16)$

Method: Āryabhaṭa’s division:

• $60 = 16 \times 3 + 12 \implies \gcd(16, 12)$
• $16 = 12 \times 1 + 4 \implies \gcd(12, 4)$
• $12 = 4 \times 3 + 0 \implies \text{remainder } 0$
$\gcd(60, 16) = \mathbf{4}$
Problem 2 $\gcd(51000, 81000)$

Method: Euclidean division:

• $81000 = 51000 \times 1 + 30000$
• $51000 = 30000 \times 1 + 21000$
• $30000 = 21000 \times 1 + 9000$
• $21000 = 9000 \times 2 + 3000$
• $9000 = 3000 \times 3 + 0$
$\gcd = \mathbf{3000}$
Problem 3 $\text{prime}(n)$ Check

Specification: A prime has exactly two divisors: $1$ and itself.

1. Compute $L = \text{divisors}(n)$.
2. Count elements in $L$.
3. If length is exactly 2, return True; else False.
$\text{length}(L) == 2$

Chapter Summary

Key Takeaways & Concept Summary

Page 50
✅ Core Foundations
  • Algorithm Defined: A systematic, step-by-step procedure of primitive operations to solve a problem.
  • Loops & Conditionals: We repeat instructions over ranges (e.g., for each $j \in [1, n]$) and execute steps conditionally (if $j$ divides $n$).
  • Data Structures: Variables and sorted lists allow us to store, organize, and quickly retrieve intermediate results.
✅ Correctness & Efficiency
  • Proof of Correctness: Every algorithm requires a mathematical justification explaining why it always produces the right answer.
  • Efficiency Analysis: Naive algorithms take steps proportional to the magnitude of the number (e.g., $N$ steps).
  • Place-Value Power: Āryabhaṭa’s division GCD reduces steps to be proportional to the number of digits ($\approx \log_{10} N$).
